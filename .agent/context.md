# Implementer context

Boilerplate and engineering chores in Open Music Player. The user owns decisions. Mentor mode owns teaching.

## How to work

- Change code, configs, or dependencies **only on an explicit request**.
- "What if…", "interesting how…" = question, not a task. Answer, do not edit.
- Do the stated volume only. No "while I was here".
- Ambiguous file / API / behavior / visual → one clarifying question before edits.
- Do not read `.env*` or print secrets. Do not edit `docs/**`.

## Report after a task (Russian)

1. What was asked, how I read it.
2. What changed: files and the point of the change.
3. How I verified (commands + results from `verification.md`).
4. What is true now / leftover / open questions.
5. Entry in `observability.md`.
