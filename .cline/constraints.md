# Ограничения агента

## Не читаю

- `.env`, `.env.*` — секреты; значения не вывожу ни в чат, ни в файлы. `.env.example` — только если задача прямо про переменные окружения.
- `.cursor/**` — включая правила. Менторский протокол из `.cursor/rules/nuxt-mentor.mdc` для меня больше не действует (ранее в этой сессии я его читал).
- `docs/**` — читаю, только чтобы свериться с этапами и прошлыми решениями; не правлю.
- `node_modules/**` — кроме точечных исходников, когда нужно доказать поведение (например, текст ошибки Vite). Такие обращения указываю в отчёте.
- `.git/**` — внутренности; `git status`, `git log` использую только на чтение.

## Не меняю без прямого запроса

- Код в `app/**` — включая файлы пользователя.
- `nuxt.config.ts`, `tsconfig.json`, `.gitignore`, `README.md`, `package.json`, `package-lock.json`.
- `docs/**` — заметки проекта ведёт не агент.
- Git-состояние: никаких `commit`, `push`, `branch`, `checkout`, `reset`, `clean`.
- Зависимости: никаких `npm install`/`uninstall`, в том числе тест-инструментов (`vitest`, `eslint`).
- Генерируемые `.nuxt/**` — читать можно как справку, править нет (перегенерируются сами).

## Технические рамки

- Никакого Tailwind и прочих «этап-14»-библиотек до соответствующего этапа.
- Никакого `process.client` — только `import.meta.client`.
- Не забегать вперёд по плану (`project-plan.md`) без запроса.
- SSR-совместимость не ломать: browser API и `localStorage` — только на клиенте.

## Моя зона

- `.clibne/**` — служебные заметки агента, правлю свободно.
- Исключение: изменение описания моей роли/правил поведения — только с согласия пользователя.

## Если задача требует выйти за рамки

Останавливаюсь, объясняю, какой файл или действие потребуется и почему, и жду решения.
